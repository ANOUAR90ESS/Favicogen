# Running as an Android and iOS app

The studio ships as a website and as a native app from the same source. Capacitor
wraps the built web app in a native shell; the generators, the ZIP builder and the
whole studio are the same code in both.

## What changes between the two

Almost nothing needs to know where it is running. Two things do, and both fail
*silently* when they get it wrong, which is why they are handled centrally rather
than at each call site.

**Handing over a file.** A WebView ignores `<a download>`. It does not throw and
it does not warn — the click simply does nothing. Every export in the app funnels
through `downloadBlob` in `src/utils/download.ts`, which checks the platform and,
on a device, writes the bytes into the app's cache directory and opens the system
share sheet on them. That sheet is where "Save to Files", "Downloads" and every
other destination live. The staged copy goes to Cache rather than Documents
because the user is choosing where the file belongs; leaving a second copy behind
would be a file they never asked for and cannot see.

The outcome is reported back to the UI as one of three things — `shared` (the
user got the sheet), `saved` (bytes written, sheet would not open) or `failed`.
A failure is never reported as a save: announcing a file that is not there is
worse than saying nothing.

**Reaching the API.** In a browser the app is served by the same Express process
that owns `/api`, so a relative path is correct and needs no configuration. A
native shell has no server behind it: its origin is `capacitor://localhost` on
iOS and `http://localhost` on Android, and `/api/ai/...` resolves to a host that
does not exist. A native build must therefore be told where the deployed server
is, at build time.

## Building

```bash
npm install
npm run sync:native      # builds the web app and copies it into both platforms
npm run open:android     # opens Android Studio
npm run open:ios         # opens Xcode (macOS only)
```

`sync:native` runs `build:web`, which is `vite build` alone — deliberately not
the full `npm run build`, which also emits `dist/server.cjs`. The Express server
has no business inside an app bundle.

Re-run `npm run sync:native` after every web change. The native projects hold a
*copy* of the build, so editing `src/` and rebuilding the app without syncing
ships the previous version.

### Configuring the API for a native build

```bash
VITE_API_BASE_URL=https://your-deployed-server.example npm run sync:native
```

Without it the AI generator says plainly that this build has no server, instead
of offering a button that can only produce a network error. Everything else in
the studio works with no server at all — the generation is local.

The server also has to accept the app's origin. It reads `ALLOWED_ORIGINS`:

```bash
ALLOWED_ORIGINS=capacitor://localhost,http://localhost
```

Both are needed if you ship both platforms — iOS uses the first, Android the
second. Nothing is allowed by default, which is why this is an explicit step
rather than something already configured.

## Before the first store upload

- **`appId`** in `capacitor.config.ts` is `com.favicogen.studio`. Both stores key
  a listing to it, and changing it after a release starts a *new* app, so settle
  it first. The app's display name and the bundle id do not have to match.
- **App icons and splash screens** are not generated by this setup. The studio
  itself produces the Android mipmap set and the iOS 1024px icon — export a brand
  package and drop the `android/` and `ios/` folders from it into
  `android/app/src/main/res/` and `ios/App/App/Assets.xcassets/`.
- **Signing** — an upload key for Play, a distribution certificate and profile for
  the App Store. Neither is in this repo and neither should be.

## What has been verified, and what has not

Verified here, in a browser and in the test suite:

- The browser download path is unchanged: a real export downloads a 278 KB PNG.
- On a native platform the anchor path is *not* taken, so the silent no-op cannot
  happen.
- A save that fails, and a bridge that never answers at all, both report a
  failure rather than a false success or nothing.
- Safe-area padding is zero in a browser — the insets add no stray gap.
- `npm run sync:native` completes and copies the build into both projects.

**Not verified here, and it needs real hardware:** the native save itself. This
container has no Android SDK, no Xcode and no device, so no APK or IPA was built
and no file was written through the real bridge. A simulated shell cannot stand
in for it — stubbing the Capacitor global is overwritten by `@capacitor/core` as
soon as any plugin chunk loads, and calls into a bridge that is not there simply
never return.

The first run on a device should check: an export reaches the share sheet, the
file that lands is the right size and opens, Android's back button closes a
dialog rather than the app, and the toolbar clears the notch.
